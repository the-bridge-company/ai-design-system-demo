One filter pattern everywhere. Select gets `inlineLabel`: the filter's name inside the trigger in secondary text, then the value in default text and the chevron ("Status Waiting", "Product All products"), the trigger hugging its content and named by both ("Product: All products"). `multiple` with `values` and `onValuesChange` picks several values, the list staying open while options are ticked, and `displayValue` sums them up ("In progress", "Leo +1"). Studio's filters all use it, at the md control height beside the search field and the view switch, and all take several values (people, products, families and statuses combine): Library review (Status, Asked by, Product), Explorations and Being built (Status, Product, Person, "Everyone" now reads "Person Everyone"), and the Family filter of Components, the Storybook and team components and the library's component pages ("Family All"). One rule for every filter: nothing ticked is the filter's all word ("Not shipped yet", "In progress", "Everyone"), never an option among its own members; each option carries its count tag; an option with nothing in it is not listed; the trigger reads the first ticked option then "+N" ("Status Being built +1"), never "2 statuses". On a phone the filters are one row that scrolls sideways inside itself, never the page, with a fade on the edge that hides a filter. An inline-label trigger takes the DS focus ring (outline and offset) instead of the inset field line, and every Select trigger is positioned so its visually hidden parts never escape a scrolling row.
